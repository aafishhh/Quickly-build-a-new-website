# 页面块区模板：Blog（列表页 + 文章页）

## Overview

「页面块区 skill」家族按页面类型逐类覆盖**单页内部的块区结构**。本 skill 覆盖 **Blog 两类页面**，分两层：

1. **骨架层（本 skill 固定）**：块区数量、顺序、职责写死，所有网站复用一致
2. **皮肤层（基准站档案，同样写死）**：每个基准站的实际视觉规格（对齐/宽度/元信息字段/TOC 形态/Share 有无/卡片构成）逐站建档。**做一个项目锁定一个站的档案，整站照抄**——皮肤之间不混搭、不临场发挥、不做"可选项"。要改皮肤 = 改这个 skill 的档案，不是项目里临场调

**两个铁律**：
1. **配色/字体/主题色不在此定**：那是产品主题的事。但**布局几何（对齐、列宽、封面位置、元信息字段构成）属于皮肤档案，写死跟站走**，不归产品主题自由发挥
2. **产品定制组件与 SEO 内容不归此 skill**：Sticky 导航、页脚只标位置；H1/导语/正文/FAQ 的写法归 SEO 内容规则 skill（`blog-seo-writing`）

**历史教训（为什么皮肤也要写死）**：只固定骨架时，两轮实现都被用户判"和参考站两模两样"——骨架对了但皮肤（图片驱动 vs 纯文字、居中 vs 左对齐、元信息带不带日期）全靠临场猜，且凭截图猜结构出过实测错误（把参考站内嵌广告示例卡误读为正文容器）。结论：**视觉规格必须逐站实测建档，实现前先解剖基准站 DOM，不凭截图猜**。

## 工作流（每次做博客页必走）

1. **确认基准站**：开局先问用户"要对齐哪个站？"——用户心里几乎总有一个具体网站。没指定则默认用下方档案之一，并告知用户
2. **解剖基准站（动手前必做）**：Playwright 全页截图（顶部/中部/底部）+ DOM 提取（每块的 class、容器宽、列宽、对齐方式、元信息字段构成）。**截图只能看到"有个白块"，看不出它是正文容器还是内容里的示例卡——结构判断以 DOM 为准**
3. **套骨架 + 锁皮肤**：块区按骨架表实现；几何参数从皮肤档案抄，不自拍数字
4. **交付前自检**：与基准站逐 block 并排截图 diff + 走一遍下方验收清单，diff 通过再交
5. **冲突裁决**：皮肤档案与骨架默认值冲突时（如 foreplay 无 Published/Updated 日期），**以皮肤档案为准**，骨架只保证块齐全与顺序

## 固定块区结构（骨架层）

> 骨架参考源：worthcodes.com。块区数量、顺序、职责写死。

### Blog 列表页（/blog/）固定块区

| # | 块区 | 作用 | 固定内容 |
|---|---|---|---|
| 1 | **Sticky 导航（产品定制占位）** | 全站入口 | 复用产品导航组件（Logo+栏目+CTA），位置在此，内容产品定 |
| 2 | **Hero 标题区** | 确立博客定位 | Eyebrow 标签（可选，看皮肤档案）+ H1 标题 + intro 副标题。对齐方式/宽度看皮肤档案 |
| 3 | **「最新文章」双栏区** | 头条曝光 + 热门引流 | 左 = 最新文章大卡（封面 + 标题 + 摘要 + 元信息）；右 = `aside` Popular posts（标题 + 文章列表）。具体样式看皮肤档案 |
| 4 | **「Explore more」区块** | 全量内容入口 | 小标题区（H2 + 副标题）+ Topic 分类筛选 pills + 文章卡片网格 |
| 5 | **页脚（产品定制占位）** | 全站收尾 | 复用产品页脚，位置在此，内容产品定 |

### 单篇文章页（/blog/<slug>/）固定块区

| # | 块区 | 作用 | 固定内容 |
|---|---|---|---|
| 1 | **Sticky 导航（产品定制占位）** | 全站入口 | 复用产品导航组件，位置在此，内容产品定 |
| 2 | **面包屑** | 层级定位 | 固定为：`Blog / <当前文章标题>`，Blog 链接回列表页 |
| 3 | **H1 标题** | 文章标题 | 位置在此；对齐/宽度看皮肤档案；写法归 SEO skill |
| 4 | **导语** | 摘要/开局 | description 作为开头段；文案归 SEO skill |
| 5 | **元信息行** | 阅读前信息 | 字段构成**由皮肤档案写死**（各站不一样，见下） |
| 6 | **封面图** | 视觉入口 | 位置（页面级 vs 正文列内）与尺寸**由皮肤档案写死** |
| 7 | **正文** | 核心内容 | 桌面三栏 `[左TOC | 正文 | 右侧栏]`，移动端侧栏隐藏。TOC 形态、右栏内容、正文是否包卡**由皮肤档案写死**。正文每个 H2 带 `id` 锚点，TOC 滚动联动高亮（IntersectionObserver） |
| 8 | **FAQ 区** | 打消疑虑 | H2「Frequently asked questions」+ H3 问题 + 段落答案，与 JSON-LD `FAQPage` 逐字一致 |
| 9 | **Related guides** | 留住读者 | 区头（eyebrow + H2 + View all 链接）+ 3 列文章卡片，复用共享卡片 |
| 10 | **返回链接** | 回到列表 | `← Back to all guides`，链接回列表页 |
| 11 | **页脚（产品定制占位）** | 全站收尾 | 复用产品页脚，位置在此，内容产品定 |

> 骨架**无定制点**：各块是固定的，不做「可选/按需」。布局细节不在此展开——全部下沉到皮肤档案。

## 基准站皮肤档案（视觉层，逐站写死，锁定一个照抄）

> 规则：**一个项目锁定一个站的档案，整站一致**。不混搭（不许 A 站的对齐 + B 站的 TOC）、不临场调参数。档案与实测有出入时，以重新解剖的 DOM 为准并更新本档案。

### 档案 A：worthcodes.com（居中式，促销/折扣博客）

| 维度 | 固定值 |
|---|---|
| 列表 hero | 居中 `max-w-[820px]`：mono eyebrow「Blog」+ H1 + intro（`max-w-[640px]`） |
| 列表卡片 | 封面图（大卡 h-240）+ H2/H3 + 摘要 2 行截断 + 作者/阅读时间 |
| 分类筛选 | Topic pills（All / Brands / Coupon Codes / Reviews / Tutorials） |
| 文章页 H1 | **居中**，`max-w-[680px]` |
| 元信息行 | 头像 + 作者名 + `Published 日期` · `Updated 日期` + `✓ Last verified 日期`（绿色徽章）+ 阅读时间 |
| 封面 | **页面级居中独立块**，`h-[280px]`，`max-w-[680px]` |
| TOC | 左栏，标题「Table of contents」+ **有序列表**（编号），滚动联动 `.is-active` |
| 右侧栏 | Popular posts 列表 |
| 正文容器 | 平铺在页面背景上（无白卡） |
| Share | 无独立 Share 区块 |
| 卡片封面 | 纯色块 + 大写字标 + 标签（非真实图）；产品可换真实图，位置不变 |

### 档案 B：foreplay.co（左对齐，深色阅读面板型）※ 本次 DOM 实测

| 维度 | 固定值 |
|---|---|
| 列表 hero | H1 + 一句具体描述，无 eyebrow，无副标题 |
| 列表卡片 | **作者头像 + 作者名在标题上方**（信任排版）+ 封面图主体 |
| 文章页头部 | 面包屑 / H1（`text-display-h4`）/ 导语**全部左对齐**，与正文列同左边 |
| 分隔线 | 导语后有一条 `blog-line` 分隔线再进三栏区，线宽 = 正文列宽 |
| 元信息行 | **只有头像 + 作者名，无日期**（Published/Updated 不上页面，dateModified 只进 JSON-LD） |
| 封面 | **在正文列内部顶端**（约 752×440），不是页面级独立块 |
| TOC | 左栏，**无编号**；当前段落 = 左侧竖条 + 文字变亮（`.is-active`） |
| 右侧栏 | **产品 CTA 卡**（如 "Start your free trial"），sticky 常驻跟随 |
| 正文容器 | **平铺在页面背景上，无白卡**（实测确认） |
| Share | 无 Share 区块 |
| 侧栏收敛 | TOC/CTA 卡 sticky 最多到正文底部，Related 区无残留 |

### 档案 C：trendtrackpromocode.com（图片驱动型）※ 截图级，未拆 DOM，用前需实测补全

| 维度 | 固定值 |
|---|---|
| 列表 | **纵向堆叠大卡**：封面图占满卡片顶部（圆角 20px、带阴影），日期在标题上方；图是视觉主角 |
| 列表 hero | H1 "XX Blog" + 一句具体描述 |
| 文章页封面 | **900px 宽大封面**（`rounded-[20px]`），与正文列同宽 |
| 正文列 | `lg:max-w-[900px]` |
| 元信息 | 日期在标题上方（列表卡）；文章页元信息构成需实测补全 |
| TOC / Share | 需实测补全后再锁定 |

> 新增档案的流程：解剖一个新基准站 → 按上表维度逐项实测填表 → 追加档案，编号续排。

## 复用共享组件

- **导航 / 页脚**：产品定制占位，博客页只引用位置
- **文章卡片**：列表 Explore more 卡片、Related 卡片、Popular 列表用**同一套卡片**，卡片构成看所锁皮肤档案
- **Blog 艺术封面**：跟皮肤档案走（worthcodes 用色块+字标；foreplay/trendtrack 用真实图），锁定哪个档案就用哪种

## 交付前验收清单（自检，逐项过）

- [ ] 基准站 DOM 已解剖，布局参数全部来自皮肤档案（无自拍数字）
- [ ] 逐 block 与基准站并排截图 diff 通过（列表页 + 文章页，桌面 + 移动端）
- [ ] 头部对齐方式与档案一致（居中 or 左对齐）
- [ ] 元信息字段与档案逐字一致（带不带日期、有无 verified 徽章）
- [ ] 封面位置与档案一致（页面级 vs 正文列内）且真实有图
- [ ] TOC 形态与档案一致（编号 or 竖条高亮），H2 锚点可跳转
- [ ] 右侧栏内容与档案一致（Popular or CTA 卡），sticky 止于正文底部
- [ ] 正文容器与档案一致（无白卡 / 有卡），Related 区无侧栏残留
- [ ] Share 区块按档案（三家档案均无 → 默认不做）
- [ ] FAQ 与 FAQPage JSON-LD 逐字一致
- [ ] 卡片三处同款（Explore more = Related = Popular）

## 与上层衔接

- **输入**：`mvp-scoping` 的页面清单已包含 Blog 页 → 本 skill 细化其块区
- **SEO**：H1/导语/正文/FAQ/slug/图片/internal-link 写法 → `blog-seo-writing`
- **输出**：块区结构 + 皮肤档案交给 `tool-site-foundation` / 开发实现

## 注意事项

- **只定块区与几何，不写代码**：实现交给 tech skill
- **骨架无定制点，皮肤无混搭**：块区写死；皮肤锁定单站档案照抄，改皮肤 = 改本 skill
- **解剖先于实现**：动手前必须抓基准站 DOM，截图只用于视觉 diff，不用于结构推断
- **导航/页脚是产品级组件**：产品自定内容，博客只标位置
- **SEO 内容不在本 skill**：写法归独立 SEO 内容规则 skill
- **Last verified / Evidence log**：仅档案 A（促销/折扣博客）使用；档案 B/C 不带
- **左侧 TOC 必须有**：形态跟档案（A=编号列表 / B=竖条高亮）
- 与 `git-worktree-isolation` 配合：博客模块在独立 worktree/分支开发
