# 构造 MVP：页面清单与信息架构

## Overview

立项 skill（new-website-ideation）回答「**为什么做**」——用户、痛点、凭啥赢、最小做哪些功能（08-prd.md）。
本 skill 回答「**MVP 由哪几类页面/模块构成**」——把 MVP 范围翻译成**页面清单层面**的信息架构：

- **页面类型清单**：MVP 需要哪几类页面/模块（如：首页、工具内页、博客页、关于页、工作台、登录、定价、账户）
- **每类页面职责**：每一类页面是干什么的（一句话）
- **页面间导航关系**：哪些页面可达哪些页面，核心链路怎么串

**页面类型由什么决定**（四股来源，按确定性分层，竞品不是决策源只是查漏网）：
1. **基础底座（无条件必有，与业务无关）**：About / Contact / Privacy Policy / Terms of Service / Blog——任何网站都有，不用从零想、不用竞品给
2. **商业模式（谁付费决定）**：要不要收钱 → 加 Pricing；要不要账号/额度/任务历史 → 加 登录 / 账户中心 / 工作台。来自立项 08-prd「谁付费、怎么收」
3. **MVP 核心用例（最定制）**：首页 / 工具内页 / 结果页——由「核心做什么动作」决定，这是最需要自己设计的部分
4. **竞品架构（只做查漏，不当决策源）**：列完 ①②③ 后用竞品核对「行业惯例核心页我是不是漏了」，**不照抄竞品全貌**（成熟竞品的帮助中心/多语言/case study 大多 MVP 阶段不该有）

决策路径：**商业模式+核心用例定核心页 → 基础底座无条件补齐 → 竞品核对查漏 → 砍掉 MVP 不需要的页**。

**边界（重要）**：本 skill **不管单页内部块区结构与 UI 细节**。每个页面的块区布局、UI 样式，由后续独立的「页面块区/UI」skill 逐类覆盖（首页一类、博客页一类、工作台一类……）。本 skill 只定位「**有哪些页、每页干嘛、怎么连**」，把「每页长什么样」留给对应页面的块区 skill。

四层分工（边界清晰、逐层细化）：
| Skill | 回答的问题 | 产出 |
|---|---|---|
| `new-website-ideation` | 为什么做（用户/痛点/最小做啥） | `08-prd.md` 业务结论 |
| `mvp-scoping`（本） | MVP 有哪些页、每页干嘛、怎么连 | 页面清单与信息架构 |
| 页面块区 skill（另行建） | 每个页面内部块区结构 + UI | 逐页的块区/UI 规范 |
| `tool-site-foundation` | 用什么技术做（技术栈/基建） | 基建方案 |

## Workflow Decision Tree

- 已读完 `08-prd.md`、要定 MVP 页面清单 → 从 Step 1 走全流程
- 只有想法、没立项 → 先建议跑 `new-website-ideation` 有 `08-prd.md` 再进本 skill
- 页面类型已定，只差某类页面的归属/职责 → 跳到 Step 2 单条补
- 有参考站/竞品 → Step 1 **作为最后查漏网**用（不照抄全貌），页面主体由商业模式+核心用例+基础底座决定

## Step 1: 页面类型清单（20-pagemap.md）

先读 `08-prd.md` 锁定 MVP 范围与「不做」清单（本 step 的边界来源），然后**按四来源分层列页面**：

1. **基础底座（无条件必有，直接列入，不必问）**：
   - `About`（关于我们） / `Contact us`（联系我们） / `Privacy Policy`（隐私政策） / `Terms of Service`（服务条款） / `Blog`（博客）
   - 这 5 页**任何网站都必选**，不依赖业务类型；且高度同构（尤其 Privacy/Terms 模板化），适合交给「页面块区 skill」做成**通用模板**一次复用
2. **商业模式页（来自 08-prd 谁付费/怎么收）**：有付费 → `Pricing`；有账号/额度/任务历史 → `登录` / `账户中心` / `工作台`
3. **MVP 核心用例页（最定制，来自核心动作）**：`首页`（入口+引导） / `工具内页`（完成核心动作） / 必要时 `结果页`
4. **竞品查漏（最后一步，不当决策源）**：对照参考站核对「行业惯例核心页有没有漏」，**不照抄竞品全貌**

最后**统一砍页**：对照「不做」清单，把 MVP 不需要的页面类型砍掉，只保留核心链路。

- **每类职责一句话**：每类页面是干什么的（首页=入口+引导；工具页=完成核心动作；工作台=任务/结果管理…）
- **以「页面类型」为单位**，不拆单页内部（单页块区/UI 由后续块区 skill 覆盖）

每类标 `[assumption]` 指出未经用户确认的页面必需性。**此处产出的是「有哪些页」，而不是每页长什么样**——块区/UI 交给后续块区 skill。

## Step 2: 页面间导航（21-navigation.md）

- **可达关系**：哪些页面类可达哪些（导航栏 / 页面内 CTA / 登录墙）
- **核心链路**：连一遍主链路——用户从哪进 → 到哪页完成核心动作 → 去哪看结果/管理（不跳页、闭环）
- **画图**：文本层次或 mermaid 图表达页面关系（页面类型节点，不画单页内部）

## Step 3: 汇总页面清单（22-mvp-summary.md）

把 1-2 组装成给后续块区 skill / 建站的页面清单：
- 页面类型清单（每类一句话职责）
- 导航关系 + 核心链路
- 所有 `[assumption]`（未经确认的页面类型）
- **明确标注**：本清单不含单页块区/UI，那部分由后续「页面块区」skill 逐类细化

产出后即可进入：对每个页面类型调用对应的**页面块区 skill** 做单页内部设计，或直接交给 `tool-site-foundation`（技术基建）。

## 注意事项

- **用户是决策者**：每步 AI 起草页面清单，用户批准后才算完成
- **只到页面类型层面**：本 skill 不产出单页块区/UI、不写样式、不写数据状态——那些是后续块区 skill 的职责，别越界
- **不重复立项**：页面类型不得超出 `08-prd.md` 的 MVP 范围；「不做」清单是硬边界
- **诚实标注**：页面必需性不确定 → `[assumption]`，等用户确认
- **产出不是代码**：本 skill 出页面清单，技术选型交给 `tool-site-foundation`
- **合规红线**：涉及伪造凭证/证件/财务类（立项已拦）的页面类型一律不列
- 与 `git-worktree-isolation` 配合：每个项目独立 worktree/分支，文档随项目走
