# SEO 落地页写作规范（产品 / 服务 / 功能页）

> 由用户完整调教的固定标准整理，作为所有 **SEO 落地页**（首页 + 销售型落地页：产品页/服务页/功能页）的强制规范。**顺序不能乱，校验不过不许交付。**
>
> 与 `blog-seo-writing`（博客文章页）**平级、互不套用**：落地页承接「商业/交易意图」词，博客承接「信息意图」词。

## 适用范围：本 skill 管什么 / 不管什么

| 页面类型 | 用什么 skill | 处理方式 |
|---|---|---|
| 博客文章页 | `blog-seo-writing` | /blog/xxx 单篇文章（信息意图）|
| **首页 + 销售型落地页**（产品/服务/功能页） | **本 skill（homepage-seo）** | 品牌/转化门面（商业意图）|
| 导航/目录/索引页 | **不适用**（另订或不做标准化） | 网址导航、类目目录、索引页 |
| 会员/账户/工作台页 | **不适用**（登录后页通常 noindex）| 登录、账户中心、数据工作台 |
| 工具/功能页（实际交互） | **边界外**（交互特殊，按需另行考虑）| 在线工具、产品实际操作页 |

**本 skill 管**：首页 + 销售型落地页（产品/服务/功能页）的定位与关键词、TDK、页面结构参考、文案规则、内链/图片/技术、发布后、交付验证。
**本 skill 不管**：博客正文（归 `blog-seo-writing`）；导航/会员等特殊类型（另议）。

## 一、定位与关键词（动笔前确认）

1. **先判词性**：落地页只承接「**商业/交易意图**」的词（产品词、功能词、品牌词、"best X for Y" 类、价格词）。
   **信息意图**的词（how to / what is）归博客，**不要硬塞进落地页**。
2. **一页一意图**：一个页面只打 **1 个主关键词 + 2–3 个紧密变体**，不贪多。
3. **防自我蚕食**：确认站内没有另一个落地页在打同一关键词；相近页面必须**明确主从分工**。
4. **竞品研究**：抓 SERP 前 5 名（**优先看同类功能页而非博客**），记录页面结构、卖点顺序、信任要素（评价/数据/logo 墙）、CTA 数量与位置。

## 二、TDK 规范

- **Title**：50–60 字符，格式「主关键词 - 品牌名」或「主关键词 | 价值点」，核心词前置
- **Description**：150–160 字符，「功能是什么 + 关键差异化卖点 + CTA」，带 **1 个数字或具体承诺**
- 直接给一版方案 + 一句话策略说明；写完后报**实际字符数**

## 三、页面结构规范（参考骨架，顺序可按产品调整）

> **⚠️ 页面结构不是固定锁死的**：下方是销售型落地页的**常见板块骨架**（自上而下的推荐顺序）。
> 每页的**实际板块与其顺序**以产品需要 + 竞品调研为准——页面块区选型交给 `page-block-home`（竞品调研方法论）。
> 本 skill 只保证：**这些板块若出现，其 SEO 职责按以下写**。

1. **Hero**：H1 含主关键词（50–60 字符内）+ 一句副标题说清「给谁解决什么」+ 首屏 1 个主 CTA
2. **痛点/价值段**：3 个左右核心卖点，每条 = 小标题（含变体词）+ 2–3 句展开
3. **怎么运作**：3 步以内，讲清使用流程
4. **信任要素**：数据、客户评价、案例或对比表（至少一种；数字必须有出处）
5. **对比/差异化段**：和替代方案比，写「适合谁 / 不适合谁」
6. **FAQ**：4–6 个购买前真实疑虑（价格、退款、安全、与竞品差异），答案 ≥70 字符、不以冒号结尾，**问题与可见文本逐字一致**（保 FAQ 富摘要）
7. **尾部 CTA**：重复主 CTA + 一句风险消除文案（免费试用 / 随时取消）

> 上述板块可增删、可调序（例如工具页可能把「怎么运作」提前）。**真正的板块结构决策**以 `page-block-home` 的竞品调研选型为准。

## 四、文案规则

- **卖点写结果不写功能**（"3 分钟出片" 优于 "支持批量渲染"）
- 短句为主，段落 ≤3 行；动词开头，删空话
- **主关键词密度 2%–3%**（按正文总词数算，写完报出实际值和出现次数）
- **首屏、至少 1 个 H2、FAQ 各至少出现 1 次**；任何**单段超过 3 次**就算堆砌，必须改写
- 优先用变体/同义词分散，**不许为凑密度硬塞**
- **每屏尽量有一个可点击的下一步**，CTA 文案具体化（不用 "Learn more"）

## 五、内链 / 图片 / 技术规范

- **内链 2–4 条**：必做 1 条链首页（锚文本 = 品牌名），其余链相关功能页或博客
  （博客做信息承接，落地页做转化）；所有链接发前逐一验证
- **出站链接**：只链权威佐证来源，`rel="nofollow"`（有意合作的佣金链接用 `sponsored`）
- **图片**：文件名含关键词；`alt` = 人类可读描述；压缩为 **WebP、单图 ≤200KB**、`<img>` 带宽高（防布局抖动）
- **Open Graph**：`og:title` / `og:description` / `og:image` 齐全（og:image **1200×630**）
- **slug** 规则同博客：**定死不改**，小写连字符，含核心关键词
- **canonical / hreflang**：多语言站按 locale 加 alternate + `x-default`（首页 x-default 指向 en 版主入口）

## 六、发布后 24 小时内

- 提交 **Google Search Console**（新 URL 检查 → 请求编入索引）
- 确认 **sitemap 已更新**、页面可被发现

## 七、交付与验证

- 交付时列出：TDK 及字符数、**页面区块大纲**、关键词密度（次数/总词数/百分比）、内链清单（锚文本→URL）、**CTA 位置清单**、slug 与图片 alt 清单
- **任何校验不过都停下来改，不许带病交付**
- 不确定的事实、无法核实的数字先问用户，**不许编造**

## 与页面块区 skill 衔接

- `page-block-home` 定「页面块区结构」（竞品调研选型：板块清单 + 顺序 + 每块样式）
- 本 skill 定「**这些板块里写什么**」的 SEO 规则（H1/TDK/密度/内链/CTA 位置）
- 即：**块区 skill 给骨架（板块放哪、顺序），本 skill 给内容规则（写什么、怎么做 SEO）**，二者配套

## 注意事项

- **只承接商业意图词**：产品/功能/品牌/best-X-for-Y/价格词；信息意图词（how to/what is）归博客，不硬塞落地页
- **一页一意图**：1 主关键词 + 2–3 紧密变体，不贪多
- **板块结构不是锁死的**：参考骨架可调序/增删，实际以页面块区调研（page-block-home）为准
- **文案写结果不写功能**：短句 ≤3 行、动词开头、每屏一个可点 CTA
- **硬校验不可跳过**：字符数/密度/内链/图片/slug/CTA 逐一验证
- **发布后 24h 必做**：GSC 提交 + 确认 sitemap
- **诚实**：数据有出处；无法核实的宁可不写；不确定的先问
- 与 `git-worktree-isolation` 配合：页面在独立 worktree/分支开发
