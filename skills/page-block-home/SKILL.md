# 首页块区：竞品调研 + 选型方法论

## Overview

首页是网站门面，也是「千变万化」的一页——**它的块区顺序和每块样式不能写死，必须靠调研竞品/优秀产品后决策产出**。

这个定位与 `page-block-foundation`（基础页固定骨架）形成对照：

| | 基础页（About/Contact/Privacy/Terms） | 首页（Home/Landing） |
|---|---|---|
| 内容 | 恒常（每站都要） | 每站不同 |
| 结构 | **固定骨架**，可复用 | **调研决策**，靠竞品推导 |
| skill 形态 | 给模板照抄 | 给方法论，产出是调研结果 |

**本 skill 核心能力**：拿到 5 个竞品首页 → 拆解成可对比的块区清单 + 每块样式 → 归纳共性 + 亮点 → 结合自家产品选出块区方案。

**沿袭家族铁律**：
- **块区=产出物**（调研后得出的方案），**视觉=产品皮肤**（每个块区样式参考竞品后自定）
- **导航/页脚=产品定制占位**（本 skill 只标「这个产品要不要、长什么样」的调研问题，不写死内容）
- **SEO 独立**（本 skill 只管块区与样式；首页 + 销售型落地页等常见落地页的 SEO head/关键词/schema 交 `homepage-seo`，博客页交 `blog-seo-writing`，导航/会员等特殊类型另议）

**与上层衔接**：
- 输入：`mvp-scoping` 的页面清单（首页必在清单里）+ 一个核心关键词或竞品 URL；建议先过 `mvp-function-flow`（首页承载的功能动作）再定块区
- 输出：首页块区方案（块区清单 + 顺序 + 每块样式参考）交给 `tool-site-foundation` 实现

## 工作流：调研 → 归纳 → 选型

### 第 1 步：获取调研对象（5 个竞品首页）

skill 启动时，取前排 5 个竞品首页，输入二选一：

- **用户指定**：用户直接给竞品首页 URL
- **用户给核心关键词**：用核心关键词搜索，取搜索结果前排 5 个网站的首页

> 若用户给了 URL 但不够 5 个、或想多看同行业者，可补搜该行业头部网站的首页。

### 第 2 步：逐个拆解（块区 + 每块样式）

对每个竞品首页，拆成一张结构卡：

```
竞品：<域名>
块区顺序：1) Header  2) <块区名>  3) <块区名>  …  n) Footer
每块样式：
- Header：<固定导航/吸顶/汉堡/含CTA>
- Hero：<主标语+副标+CTA / 分屏产品截图 / 终端输入条 / 全屏视频…>
- Features：<卡片网格/图文交错/数字罗列…>
- Showcase：<产品截图/用户案例/视频演示…>
- Pricing：<三档卡片/切换月年/免费试用CTA…>
- FAQ：<折叠手风琴/左右两栏…>
- CTA：<整幅色块号召/单按钮…>
- Footer：<多列/链接组/订阅条…>
```

> 抓取工具：可用浏览器抓取竞品首页实际 DOM，识别块区边界（`<section>/<header>/<footer>`、区块标题、CTA 位置），再描述每块样式。抓不到的用截图/肉眼观察补。

### 第 3 步：归纳共同模式 + 差异化亮点

把 5 个竞品的块区顺序横向对比成表：

```
块区         竞品A  竞品B  竞品C  竞品D  竞品E
Header        ✓      ✓      ✓      ✓      ✓
Hero          ✓      ✓      ✓      ✓      ✓
Features      ✓      ✓      ✓      ✓      —
Showcase      —      ✓      —      ✓      ✓
Pricing       ✓      —      ✓      —      ✓
Logos/信任    —      ✓      ✓      —      —
FAQ           ✓      —      ✓      —      —
CTA           ✓      ✓      ✓      ✓      —
Footer        ✓      ✓      ✓      ✓      ✓
```

从表里提炼两点：
- **共同项**（≥4 家都有）→ 这是该品类首页的「标配」，大概率要含
- **差异化项**（只有一两家有、且看起来是亮点）→ 可选加分项，评估要不要借鉴

### 第 4 步：选型自家首页块区（结合自家产品）

不照抄竞品，按自家产品约束筛选、排序：

1. **商业模式**（来自 `mvp-scoping`）：是否收费 → 要不要 Pricing；是否账号 → 要不要登录 CTA/工作台入口
2. **核心用例**：产品最核心的 1 个动作是什么 → 它应出现在首页最显眼位置（常是 Hero 的输入条/主 CTA）
3. **品牌调性**：参考竞品后，自家要传达什么气质 → 影响每块样式选型
4. **砍掉**：与自家无关的竞品块区（如你无付费就不放 Pricing）

产出 → **自家首页块区清单（含顺序）**，格式：

```
自家首页 <产品名> 块区方案：
1) Header（固定导航 or 吸顶）                    ← 从竞品X/Y 参考
2) Hero（<形态>，主打 <核心用例>）               ← 从竞品A 参考 + 自家定制输入条
3) Features（卡片网格 or 图文交错）              ← 从竞品C 参考
…
n) Footer
每个块区标注：参考了哪个竞品 + 自家要做的形态 + 定制点
```

### 第 5 步：每个块区的样式（参考竞品后自定）

**每个块区各自的样式不同**，不共享一套皮肤。对一个块区做样式决策：

1. 看竞品这块钱什么形态 → 挑 1-2 个最合适的作参考
2. 结合自家品牌调性 → 调整为自家形态（可参考 `design-theme` skill 的 9 个设计方向库 + 反 AI 模板化禁用词清单，见附录）
3. 落地 tokens：配色/字体/卡片圆角/间距，随块区不同而变

产出 → 每个块区一份「样式参考卡」：形态 + 参考竞品 + 自家定制。

## 附录：块区形态参考库（可选，便于快速表达）

> 这不是固定骨架，是「竞品里常见的形态」辞典——帮你给自家块区命名形态时用。真正顺序和样式以调研结果为准。

| 块区 | 常见形态 |
|---|---|
| Header | 固定导航 / 吸顶透明→实色 / 汉堡折叠 / 含 CTA 按钮 / 含登录入口 |
| Hero | 居中标语+CTA / 分屏产品图 / 终端/输入条 / 全屏视频 / 杂志级标题 |
| Features | 卡片网格(3-6) / 图文交错 / 数字指标罗列 / 双列对照 |
| Showcase | 产品截图轮播 / 用户案例 / 视频演示 / 前后对比 |
| Pricing | 三档卡片 / 月年切换 / 免费试用 CTA / 对比表 |
| Logos/信任 | 客户 logo 墙 / 数据/认证徽章 |
| FAQ | 折叠手风琴 / 左右两栏 / 分类 tab |
| CTA | 整幅色块号召 / 渐变横幅 / 单 CTA 按钮 |
| Footer | 多列链接 / 品牌+链接 / 订阅条 / 版权+政策 |

## 与上层衔接

- **输入**：`mvp-scoping` 的页面清单（首页是核心用例页）+ 竞品 URL / 核心关键词
- **输出**：首页块区方案（清单 + 顺序 + 每块样式参考）交给 `tool-site-foundation` 实现
- **其余页面**：基础页 → `page-block-foundation`，博客页 → `page-block-blog`
- **首页 SEO**：块区定了之后，首页 + 销售型落地页等常见落地页的 SEO head（title/description/canonical/hreflang/schema）与新词策略 → 交给 `homepage-seo`；博客文章页 → 交给 `blog-seo-writing`；导航/会员等特殊类型不用这套规则

## 注意事项

- **不写固定骨架**：首页块区顺序靠调研决策，不预置一张「标准序列」让人照抄
- **每块样式不同**：块区各自形态参考竞品后自定，不共享一套皮肤
- **竞品是参考不是答案**：调研完仍要按自家商业模式/核心用例/品牌调性筛选排序，砍掉无关块区
- **只定结构，不写代码**：块区方案给「是什么样 + 参考谁」，「怎么做」交给技术 skill
- 与 `git-worktree-isolation` 配合：首页在独立 worktree/分支开发
